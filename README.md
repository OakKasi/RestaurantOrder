# Restaurant Order App (แอปสั่งอาหารสำหรับลูกค้าที่นั่งในร้าน)

วิชา 01418342 การพัฒนาแอปพลิเคชันบนอุปกรณ์เคลื่อนที่
ภาควิชาวิทยาการคอมพิวเตอร์และเทคโนโลยีดิจิทัล คณะศิลปศาสตร์และวิทยาศาสตร์
มหาวิทยาลัยเกษตรศาสตร์ วิทยาเขตกำแพงแสน

แอปจัดการการสั่งอาหารและบิลสำหรับร้านอาหาร ลูกค้าสั่งจากโต๊ะได้เอง ออเดอร์ส่งเข้าครัวทันที และสั่งเพิ่มได้หลายรอบในบิลเดียว ข้อมูลเก็บใน SQLite บนเครื่อง จึงใช้งานแบบออฟไลน์ได้ ทำด้วย React Native, Expo SDK 57 และ expo-sqlite

## 2. วิธีติดตั้งและรัน

1. ติดตั้ง dependencies (เปิด Terminal ในโฟลเดอร์โปรเจกต์)

```bash
npm install
```

2. สตาร์ท development server

```bash
npx expo start
```

หรือใช้ `npm start` ก็ได้

3. เปิดแอปเพื่อทดสอบ

- มือถือจริงผ่าน Expo Go (วิธีนี้สะดวกสุด)
  - Android: เปิด Expo Go แล้วสแกน QR Code ที่ขึ้นใน Terminal
  - iOS: สแกน QR Code ด้วยแอปกล้อง แล้วเลือกเปิดใน Expo Go
  - มือถือกับคอมต้องต่อ Wi-Fi วงเดียวกัน
- Emulator / Simulator
  - กด `a` ใน Terminal เพื่อเปิดบน Android Emulator
  - กด `i` เพื่อเปิดบน iOS Simulator (ใช้ได้เฉพาะ macOS)
  - กด `w` เพื่อเปิดบนเว็บเบราว์เซอร์

## 4. สิ่งที่ทำเสร็จแล้ว

### 4.1 ระดับ ก (ทำครบทุกข้อ)

- ก1 เลือกโต๊ะและเปิดบิล: มีผังโต๊ะ 15 โต๊ะ (`TablesScreen`) เลือกโต๊ะเพื่อเปิดบิลใหม่ หรือเข้าบิลที่ยังเปิดค้างอยู่ก็ได้
- ก2 เมนูแบ่งตามหมวด: ข้อมูลตั้งต้นมี 5 หมวด รวม 35 รายการ ได้แก่ อาหารจานเดียว, ต้ม/แกง, ผัด/ทอด, อาหารทะเล และเครื่องดื่ม (เกณฑ์ขั้นต่ำคือ 4 หมวด 25 รายการ)
- ก3 เลือกจำนวนและใส่หมายเหตุ: กดเมนูแล้วจะมี popup ให้ปรับจำนวนและพิมพ์หมายเหตุ เช่น เผ็ดน้อย, ไม่ใส่ผักชี
- ก4 ตรวจรายการและส่งเข้าครัว: ดูรายการในตะกร้าได้ก่อนกดส่ง เมื่อส่งจะบันทึกเป็น 1 รอบ (`order_rounds`) ด้วย transaction
- ก5 สั่งเพิ่มหลายรอบในบิลเดียว: สั่งซ้ำในโต๊ะเดิมได้ ระบบนับรอบถัดไปให้เอง และข้อมูลรอบก่อนหน้ายังอยู่ครบ
- ก6 สรุปบิล: `BillSummaryScreen` แสดงรายการแยกตามรอบ พร้อมจำนวน ราคาต่อหน่วย ราคารวมแต่ละรายการ และยอดรวมทั้งบิล (คำนวณด้วย SQL `SUM()`)
- ก7 หน้าครัวเรียงตามเวลา: `OrderScreen` เรียงออเดอร์จากเก่าไปใหม่ (`ORDER BY order_items.id ASC`)
- ก8 เปลี่ยนสถานะอาหาร: มี 3 สถานะ คือ `pending` (รอดำเนินการ), `cooking` (กำลังปรุง) และ `served` (เสิร์ฟแล้ว)
- ก9 ข้อมูลในหน้าครัว: แสดงเลขโต๊ะ รอบที่สั่ง ชื่ออาหาร จำนวน สถานะ และหมายเหตุ
- ก10 ปิดบิลและดูประวัติ: ปิดบิลแล้วโต๊ะจะกลับเป็นว่างและเปิดบิลใหม่ได้ ส่วนบิลที่ปิดไปแล้วดูย้อนหลังได้ที่ `BillHistoryScreen`

### 4.2 ระดับ ข (ทำ 3 ข้อ จากขั้นต่ำ 2 ข้อ)

- ข1 สรุปยอดขายรายวัน: `DashboardScreen` รวมยอดขายของวันนั้น (00:00 - 23:59 น.) แยกตามหมวดอาหาร และแสดงยอดรวมทั้งหมด
- ข3 ยกเลิกรายการที่ยังไม่ได้ทำ: ในหน้าครัวกดยกเลิกรายการที่เป็น `pending` ได้ ระบบจะเปลี่ยนสถานะเป็น `cancel` และบันทึกเวลาที่ยกเลิกไว้ในตาราง `cancel_items`
- ข5 จัดการเมนูในแอป: `MenuSettingsScreen` และ `AddMenuScreen` ใช้เพิ่มเมนูใหม่ แก้ราคา และเปิด/ปิดการขายชั่วคราวด้วย Switch (`is_available`)

### 4.3 ด้านฐานข้อมูลและเทคนิค

- ตาราง SQLite 7 ตาราง มี foreign key 7 จุด และเปิด `PRAGMA foreign_keys = ON;`
- ใช้ `ON DELETE RESTRICT` และ `ON DELETE CASCADE` ตามความสัมพันธ์ของข้อมูล
- กำหนด `NOT NULL` และ `CHECK` เช่น `price >= 0`, `quantity > 0`, `status IN (...)`
- สร้าง index 2 ตัว คือ `idx_order_items_round_id` และ `idx_bills_table_status`
- ส่งออเดอร์หลายรายการในรอบเดียวผ่าน `db.withTransactionAsync`
- กันปัญหาราคาเปลี่ยนย้อนหลังด้วยคอลัมน์ `price_at_order` ใน `order_items` ถ้าแก้ราคาเมนูทีหลัง บิลที่สั่งไปแล้วก็ไม่เปลี่ยน
- ใส่ seed data ให้อัตโนมัติตอนเปิดแอปครั้งแรก และไม่ใส่ซ้ำในครั้งต่อไป
- มีฟังก์ชันและปุ่มล้างข้อมูลการขาย (`clearAllTransactionData`) เพื่อให้ผู้ตรวจทดสอบซ้ำได้

## 5. สิ่งที่ยังทำไม่ทัน

1. ข2 ค้นหาเมนู: ยังไม่มีช่องค้นหาและตัวกรองเมนูที่มีของในหน้าสั่งอาหาร ตอนนี้เลือกได้แค่ตามแถบหมวดหมู่
2. ข4 แยกบิล/ย้ายโต๊ะ: ยังย้ายรายการข้ามโต๊ะ หรือแยกบิลจ่ายเงินของลูกค้าโต๊ะเดียวกันไม่ได้
3. ข6 เมนูขายดี 10 อันดับ: ยังไม่ได้ทำรายงานจัดอันดับตามช่วงวันที่
4. ระดับ ค
   - ตัวเลือกย่อยของเมนูที่มีผลกับราคา เช่น ขนาดธรรมดา/พิเศษ, เพิ่มไข่ดาว
   - โปรโมชัน ส่วนลด ค่าบริการ และ VAT
   - ออกใบเสร็จเป็น PDF หรือต่อเครื่องพิมพ์ความร้อน
5. Image Picker: ตอนนี้เพิ่มรูปเมนูโดยกรอก URL ยังเลือกรูปจากแกลเลอรีในเครื่องไม่ได้
